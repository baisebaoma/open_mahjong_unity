## 1. 玩法背景（虹雀²）

- **126 张牌**：7 种纯色 ×1-9 + 7 种半色（相邻两色） ×1-9；花色映射为模 14 环。
- **单副本牌库**：每种牌全局只有一张 → 对手弃过的牌（现物）对该对手必然安全。
- 每副牌约 **9 次摸牌**；实测**荣和占 76% / 自摸占 24%**（这正是防守有价值的根本原因）。
- 番种结算：`points = base × fan_total`（`fan_total==0` 时 points=1）。

## 2. 目标与统计口径

**目标**：新启发式 AI 在统计意义上“明显优于”现有牌效机器人
（`user_id=2`，efficiency bot，下文称“牌效”）。

**基准协议**（`hongque_selfplay.py`）：

- **1v3 自战**：1 个新座位 + 3 个对手座位；**轮换座位**（消庄家/顺序偏差）；确定性种子。
- 指标：**锦标赛平均顺位**（1-4）；用 **95% CI（t 分布双尾）** 判断是否“明显更强”：
  平均顺位 < 2.5 即强于随机/均势；**CI 上界 < 2.5 视为统计显著**。
- 附指标：单侧 p、符号检验、每座净分。
- 分阶段验证：agent 代码块 `72011 / 72021 / 72041`，预注册块 `72101–72200`，
  验证块 `72201–72300`；跨块方差较高，结论以合并大样本为准。
- 运行方式（从 `open_mahjong_server` 目录）：

```bash
uv run --no-project --with fastapi --with scipy \
  python -m server.gamestate.game_hongque.hongque_selfplay \
  --matches 100 --base-seed 72201 --new heuristic-v3 --opponent efficiency
```

## 3. 版本演进与尝试

### v1 — 牌效机器人（基准，`efficiency_bot.py`）

纯牌效：`_structural_value`（替代距离 + 灵活性，打包 DP）。无任何计分/防守意识。
作为“要被超过”的基准存在。自战画像：均番 ≈1.84，≥6 番 ≈3.5%。

### v2 — 计分启发式（`heuristic_bot.py`，user_id=3）

> 定位说明：v2 文件**必须保留**——v3 从它导入 15+ 个内部符号（`_structural_value`、
> `_style_utility`、`_is_better_ready`、`_hypothetical_points` 等），它现在是 v3 的
> **基座库**，不是线上残留。线上 `user_id=3` 已全走 v3（`HongqueGameState.py`）；
> v2 仅作为 v3 底层 + 自战参照（`hongque_selfplay.HeuristicSeat`）与单测基准
> （`test_heuristic_bot.py`）存在。请勿删除或大幅重构，除非同步改写 v3。

在牌效距离上叠加**番种计分偏好**：`V2Value`、`_style_utility`（顺/刻/定番结构偏好）、
听牌并列用 `_is_better_ready`（slack=30）选更优听；未听从连接度排序改为
距离/灵活性/风格排序。

- 与牌效对比早期即显著领先（某块均顺 2.05），且 **CI 一度擦线**接近达成目标，
  但因跨块方差大（块 72021 +149.7 / 块 72101 +494.7 / 块 72041 +39 净分），
  单块不足以定论。
- 自战画像（20 场）：均番 2.19、中位数 2、≥6 番 5.9%、最高 11 番。

### v3 — 威胁门控防守（`heuristic_bot_v3.py`，当前版，user_id=3）

在 v2 之上加**防守层**（听牌选择、鸣牌、补牌、杠与 v2 完全一致）：

- **现物安全**：单副本库 → 对手已弃的牌必安全（genbutsu）。
- **副露方向危险**：对手副露揭示花色族与数字区间；该区间附近的弃牌危险，
  对手狂弃的花色廉价。
- **威胁门控**：仅当巡目靠后（`_WALL_START=81` 起算）且对手平均弃牌 ≥3 时
  离开纯进攻；威胁等级 = 晚局因子 × 平均弃牌。阈值 `_DEFENSE_THREAT=0.5`、
  `_STRONG_DEFENSE_THREAT=0.75`。
- **两张防守策略**：
  - **近手（min_distance < 2）**：继续进攻，平局时偏好更安全的牌；
  - **远手**：在小距离预算内折叠向最安全的弃牌
    （按 `(distance-min, danger, -flexibility, -style)` 排序）。
- `HongqueGameState.py` 每轮为 user_id=3 收集对手快照（`opponents_snapshot`），
  把 `choose_turn_plan_v2 / claim_plan_v2` 换成 v3 入口。

## 6. 已知问题与后续方向

- **v3 vs v2 尚未统计显著**：建议合并 ≥140 场（跨多块）重算 CI；高方差是主因。
- 防守层只做了“现物 + 副露方向 + 距离预算折叠”，可探索：
  读牌弃牌统计加权、`wall < 16` 尾巡强防守、自摸放弃阈值。
- 牌效机器人本身很弱（均番 ~1.8），v2/v3 相对它的领先幅度大于相对人类水平的意义；
  与 v2 的比较才是算法本身优劣的核心证据。

### 6.1 玩家建议评估（Xelnaga，2026-08-08）

Xelnaga 提出三条防守建议：**①按剩余巡目当参数；②剩余巡目 × 得分预期；
③海底刚好打绝安**。对照 v3 评估：

- **有道理、v3 已有雏形但只有一半**：v3 的 `_threat_level = late × (平均弃牌/8)` 用了
  剩余巡目（`late` 因子），但只线性放大“对手危险度”，**没有乘上自己这手牌的期望得分**。
- **最有价值的是“剩余巡目 × 得分预期”**：把“防守代价（放弃自己的赢牌期望）”和
  “风险（放铳/被抢先）”做权衡——得分预期高的手值得冒险，0 番散手该弃。这正是日麻
  “攻守判断”的标准思维。v3 目前用 `min_distance` 分近手/远手，距离 ≠ 得分预期。
- **“海底打绝安”对，且虹雀比日麻更可靠**：单副本牌库下 genbutsu 就是 100% 安全。
  v3 有 genbutsu 判定，但 `wall_empty` 参数传入后未在防守分支强制使用（仅靠 threat 间接触发）。
- **“确定胡不了就全弃”是二元思维，与实测冲突**：v3 激进防守版（威胁阈值 0.25 就弃）
  成绩 2.59，反而不如最终版 2.28——“确定胡不了”的判断不可靠，早弃浪费赢牌机会。
  最终版用**软门控 + 预算内折叠**（近手保攻、远手在距离预算内挑最安全牌）是验证过的折中。

**提炼为 v4 候选方向**：威胁门控上叠加**自身得分预期因子**（如 `expected_points` 反比
衰减防守强度）+ **海底强制绝安**；**不要**做成“胡不了就全弃”的二元开关。

## 7. v4 探索结果（2026-08-08 晚）

`heuristic_bot_v4.py` 按 §6.1 落地方向，在 v3 之上只改两处（听牌/鸣/补/杠与 v3 完全一致）：

- **得分预期因子**：防守触发后，用 `_style_utility(手牌+副露)`（做牌方向分，0–64）按
  `threat *= 1 − 0.5 × min(1, style/64)` 衰减威胁——高分潜力手更敢进攻、散手照旧防守。
- **海底强制绝安**：`wall_count ≤ 2` 且防守已触发时，无视距离预算强制打全局最安全牌
  （单副本库下 genbutsu 即 100% 安全）。

**参数探针**（1v3 自战，v4 座 + 3 v3 座）：

| 参数 | 块 | v4 均顺 | 结论 |
|------|-----|--------:|------|
| weight=0.5, wall≤2（定稿） | 72301 | 2.47 | 方向占优（p=0.39 未显著） |
| weight=0.85, wall≤4 | 72401 | 2.55 | **过度防守，反而劣化**（v3 平均 2.48）→ 回滚 |
| weight=0.5, wall≤2（定稿） | 72601–72800 合并 | **2.275** | **CI (2.125, 2.425) 上界 < 2.5 ✓，p=0.0017** |

**结论：v4 相对 v3 达成统计显著优势**（200 场，CI 上界 2.425 < 2.5，单侧 p=0.0017；
v3 三席均顺 2.53/2.57/2.625，CI 下界全部 > 2.5）。这是本系列第一次“新版本 vs
上一版本”获得统计确立（此前 v3 vs v2 仅方向性占优）。

**v4 vs 牌效**（200 场）：均顺 2.44，方向占优但未显著（牌效对手本身很弱，方差大；
保守解读为“相对 v3 不劣化对牌效的压制”）。

**教训**：得分预期因子 + 海底绝安的收益集中在“弱防守时机”（权重过高反而在强威胁下
放弃效率），且分块方差极大——**必须合并 ≥200 场再下结论**。

## 8. 自战基准并行化（hongque_selfplay.py）

v3 之前 100 场基准约 **11 分钟**（串行）。`hongque_selfplay.py` 现支持并行：

- `--workers N`：按连续种子分片（`base_seed+i` 均匀切给 N 个 worker），
  `ProcessPoolExecutor` 跑，结果按种子合并，**与串行逐位一致**（已验证 4 场并行/串行
  net=-5.7 / avg_rank=2.25 完全相同）。默认 `--workers 0` = 全核。
- 实测 100 场从 **~640 s 降到 ~95 s**（约 6.8×，吃满多核）。
- 说明：Windows spawn 下 worker 重新 import 本模块，`sys.path.insert` 已改为指向
  `open_mahjong_server`（原三跳会把 `server.py` 当顶层模块，spawn 时崩）。
- 顺位明细在 `result["per_policy_rank"]`，可直接喂 scipy 算 CI。
