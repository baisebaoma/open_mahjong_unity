## 1. 玩法背景（虹雀²）

- **126 张牌**：7 种纯色 ×1-9 + 7 种半色（相邻两色） ×1-9；花色映射为模 14 环。
- **单副本牌库**：每种牌全局只有一张 → 对手弃过的牌（现物）对该对手必然安全。
- 每副牌约 **9 次摸牌**；实测**荣和占 76% / 自摸占 24%**（这正是防守有价值的根本原因）。
- 番种结算：`points = base × fan_total`（`fan_total==0` 时 points=1）。

## 2. 目标与统计口径

**目标**：新启发式 AI 在统计意义上“明显优于”现有牌效机器人
（`user_id=2`，efficiency bot，下文称“牌效”）。

**基准协议**（`hongque_selfplay.py`）：

- **1v3 自战**：1 个新座位 + 3 个对手座位；**轮换座位**（消庄家/顺序偏差）；确定性种子。
- 指标：**锦标赛平均顺位**（1-4）；用 **95% CI（t 分布双尾）** 判断是否“明显更强”：
  平均顺位 < 2.5 即强于随机/均势；**CI 上界 < 2.5 视为统计显著**。
- 附指标：单侧 p、符号检验、每座净分。
- 分阶段验证：agent 代码块 `72011 / 72021 / 72041`，预注册块 `72101–72200`，
  验证块 `72201–72300`；跨块方差较高，结论以合并大样本为准。
- 运行方式（从 `open_mahjong_server` 目录）：

```bash
uv run --no-project --with fastapi --with scipy \
  python -m server.gamestate.game_hongque.hongque_selfplay \
  --matches 100 --base-seed 72201 --new heuristic-v3 --opponent efficiency
```

## 3. 版本演进与尝试

### v1 — 牌效机器人（基准，`efficiency_bot.py`）

作为“要被超过”的基准存在。自战画像：均番 ≈1.84，≥6 番 ≈3.5%。

在牌效距离上叠加**番种计分偏好**：`V2Value`、`_style_utility`（顺/刻/定番结构偏好）、
听牌并列用 `_is_better_ready`（slack=30）选更优听；未听从连接度排序改为

- 与牌效对比早期即显著领先（某块均顺 2.05），且 **CI 一度擦线**接近达成目标，

### v3 — 威胁门控防守（`heuristic_bot_v3.py`，当前版，user_id=3）

在 v2 之上加**防守层**（听牌选择、鸣牌、补牌、杠与 v2 完全一致）：

- **现物安全**：单副本库 → 对手已弃的牌必安全（genbutsu）。
- **副露方向危险**：对手副露揭示花色族与数字区间；该区间附近的弃牌危险，
  对手狂弃的花色廉价。
- **威胁门控**：仅当巡目靠后（`_WALL_START=81` 起算）且对手平均弃牌 ≥3 时
  离开纯进攻；威胁等级 = 晚局因子 × 平均弃牌。阈值 `_DEFENSE_THREAT=0.5`、
  `_STRONG_DEFENSE_THREAT=0.75`。
- **两张防守策略**：
  - **近手（min_distance < 2）**：继续进攻，平局时偏好更安全的牌；
  - **远手**：在小距离预算内折叠向最安全的弃牌
    （按 `(distance-min, danger, -flexibility, -style)` 排序）。
- `HongqueGameState.py` 每轮为 user_id=3 收集对手快照（`opponents_snapshot`），
  把 `choose_turn_plan_v2 / claim_plan_v2` 换成 v3 入口。

## 6. 已知问题与后续方向

- **v3 vs v2 尚未统计显著**：建议合并 ≥140 场（跨多块）重算 CI；高方差是主因。
- 防守层只做了“现物 + 副露方向 + 距离预算折叠”，可探索：
  读牌弃牌统计加权、`wall < 16` 尾巡强防守、自摸放弃阈值。
- 牌效机器人本身很弱（均番 ~1.8），v2/v3 相对它的领先幅度大于相对人类水平的意义；
  与 v2 的比较才是算法本身优劣的核心证据。

### 6.1 玩家建议评估（Xelnaga，2026-08-08）

Xelnaga 提出三条防守建议：**①按剩余巡目当参数；②剩余巡目 × 得分预期；
③海底刚好打绝安**。对照 v3 评估：

- **有道理、v3 已有雏形但只有一半**：v3 的 `_threat_level = late × (平均弃牌/8)` 用了
  剩余巡目（`late` 因子），但只线性放大“对手危险度”，**没有乘上自己这手牌的期望得分**。
- **最有价值的是“剩余巡目 × 得分预期”**：把“防守代价（放弃自己的赢牌期望）”和
  “风险（放铳/被抢先）”做权衡——得分预期高的手值得冒险，0 番散手该弃。这正是日麻
  “攻守判断”的标准思维。v3 目前用 `min_distance` 分近手/远手，距离 ≠ 得分预期。
- **“海底打绝安”对，且虹雀比日麻更可靠**：单副本牌库下 genbutsu 就是 100% 安全。
  v3 有 genbutsu 判定，但 `wall_empty` 参数传入后未在防守分支强制使用（仅靠 threat 间接触发）。
- **“确定胡不了就全弃”是二元思维，与实测冲突**：v3 激进防守版（威胁阈值 0.25 就弃）
  成绩 2.59，反而不如最终版 2.28——“确定胡不了”的判断不可靠，早弃浪费赢牌机会。
  最终版用**软门控 + 预算内折叠**（近手保攻、远手在距离预算内挑最安全牌）是验证过的折中。

**提炼为 v4 候选方向**：威胁门控上叠加**自身得分预期因子**（如 `expected_points` 反比
衰减防守强度）+ **海底强制绝安**；**不要**做成“胡不了就全弃”的二元开关。

## 7. v4 探索结果（2026-08-08 晚）

`heuristic_bot_v4.py` 按 §6.1 落地方向，在 v3 之上只改两处（听牌/鸣/补/杠与 v3 完全一致）：

- **得分预期因子**：防守触发后，用 `_style_utility(手牌+副露)`（做牌方向分，0–64）按
  `threat *= 1 − 0.5 × min(1, style/64)` 衰减威胁——高分潜力手更敢进攻、散手照旧防守。
- **海底强制绝安**：`wall_count ≤ 2` 且防守已触发时，无视距离预算强制打全局最安全牌
  （单副本库下 genbutsu 即 100% 安全）。

**口径说明（重要）**：`game_round=4` 时 `max_round=16`，即 **1 场 = 16 小局**（大场）。
`200 场 = 3200 小局`。分数非零和——**只有赢家 `score += points`，输家不扣分**，因此
“净分 = 本座得分 − 三对手平均得分”衡量的是“比对手多赢多少分”，适合做相对强弱主指标。

### 7.1 同块 A/B（2026-08-09，公平对比，各 200 场 = 3200 小局，块 73001）

| 基准 | 均顺 | 95% CI | p(单侧) | 净分 |
|------|-----:|--------:|--------:|-----:|
| v3 vs 牌效 | 2.345 | (2.185, 2.505) | 0.029 ✓ | **+1089**（≈+5.4/大场） |
| **v4 vs 牌效** | **2.335** | (2.176, 2.494) | **0.021 ✓** | **+1046**（≈+5.2/大场） |
| v4 vs v3 | 2.545 | (2.382, 2.709) | 0.706 | **−362**（≈−1.8/大场） |

结论：

- **v4/v3 对牌效都是同块显著**（p≈0.02–0.03，CI 上界 < 2.5），且 v4 不劣于 v3。
  “v4 打牌效不显著”是**跨块假象**（块 72801 的牌效有一席异常强，稀释优势）。
- **v4 vs v3 跨块不稳定**：块 72601–72800 上 v4 均顺 2.275（p=0.0017，显著领先），
  但同块 73001 上 v4 均顺 2.545（反而落后）——**单块“显著”不可信，跨块合并
  才是稳健证据**。合并定稿参数约 500 场：v4 ≈ 2.42 vs v3 ≈ 2.53，方向占优但
  **未稳健确立**。
- 净分换算：v4 vs 牌效 ≈ +5.2/大场 ≈ **+0.33/小局**；v4 vs v3 ≈ −1.8/大场。
  净分也同块波动，须合并多块再下结论。
- **净分 95% CI（2026-08-09 补算，供 PR）**：此前只报净分总和、未算置信区间。
  基准脚本现记录每场净分序列（`per_policy_game_net`）。块 72201（200 场，v3 vs 牌效）：
  净分 **+4.59/大场，95% CI (0.59, 8.58)，下界 > 0**（单侧 p=0.012）→ 得分领先统计显著；
  折合 **+0.29/小局** ≈ 领先对手平均分约 15%。同块均顺 2.355 (2.200, 2.510)（p=0.033），
  与历史跨块 2.28 [2.06, 2.50] 方向一致。**报告 PR 时给均顺 CI + 净分 CI 两条即可。**

**净分相对化（重要，避免误读绝对分）**：虹雀² 番种表最大单番 18（清一色/清一数/天和），
`points = base(≈3) × fan_total`，实测 95% 和牌 ≤25 分、中位数 6、均值约 8.7——**没有
“几百番”**，高番几乎不出现。大场总分 ≈ 16 小局 × 85% 和牌率 × 8.7 ≈ **118 分**，四座
平均约 29.5 分。因此 **v4 vs 牌效 +5.2/大场 ≈ 领先对手平均 17.7%**；换算成小局
+0.33 ≈ 每小局总分的约 4.5%。**绝对数小是 base 低 + 非零和的机制使然，不是“弱”**；
报告净分时应同时给相对百分比，别用绝对分或“几百番”做参照。

### 7.2 教训

- **分块方差极大**（同算法对在不同块上甚至方向相反），**单块 200 场不够**；
  必须同块 A/B 或跨块合并 ≥400 场。
- 均顺在“1 高手 + 3 同质弱手”下有天花板（弱手互相喂分，高手每场稳定小赚但
  难拿第一），**净分更能反映真实优势**；但净分同样要跨块合并。
- 得分预期因子 + 海底绝安的收益集中在“弱防守时机”，权重过高反而劣化（见 §7.1 前
  的参数探针：weight=0.85 时 2.55，回滚）。

## 8. 自战基准并行化（hongque_selfplay.py）

v3 之前 100 场基准约 **11 分钟**（串行）。`hongque_selfplay.py` 现支持并行：

- `--workers N`：按连续种子分片（`base_seed+i` 均匀切给 N 个 worker），
  `ProcessPoolExecutor` 跑，结果按种子合并，**与串行逐位一致**（已验证 4 场并行/串行
  net=-5.7 / avg_rank=2.25 完全相同）。默认 `--workers 0` = 全核。
- 实测 100 场从 **~640 s 降到 ~95 s**（约 6.8×，吃满多核）。
- 说明：Windows spawn 下 worker 重新 import 本模块，`sys.path.insert` 已改为指向
  `open_mahjong_server`（原三跳会把 `server.py` 当顶层模块，spawn 时崩）。
- 顺位明细在 `result["per_policy_rank"]`，可直接喂 scipy 算 CI。

## 9. 最终决定：线上提交用 v3（2026-08-09）

**决定：`user_id=3` 线上走 v3（`heuristic_bot_v3.py`），v4 保留为实验代码不入库运行。**

依据：

1. **v3 对牌效的优势是跨块稳健的**：历史上 100 场均顺 2.28、CI 上界 < 2.5（p=0.0234），
   同块 73001 再测仍显著（p=0.029）。这是本系列唯一“跨块反复确认”的显著结果。
2. **v4 vs v3 未稳健确立**：块 72601–72800 上 v4 显著领先（2.275），但同块 73001 上
   v4 反而落后（2.545）。合并约 500 场 v4 ≈ 2.42 vs v3 ≈ 2.53，仅方向占优——**达不到
   “明显优于当前版本”的上线门槛**（对比 v3 当年 vs 牌效 CI 上界 < 2.5 的标准）。
3. **v4 对牌效不劣于 v3**（同块 p=0.021 vs 0.029），但也没有额外收益——不值得为它
   承担更多复杂度（得分预期因子 + 海底绝安两条分支）。

**后续若要 v4 转正**：需跨多块（≥400 场）合并后 v4 均顺 ≤ v3 且 CI 上界 < 2.5，
同时 v4 对牌效不劣化。当前数据不满足。

v3 定稿当晚，在“把防守做得更聪明”的方向上并行试了三个独立组件，各自
整文件独立成版（沿用 v3→v4 的复制惯例），**全部只进自战、不改线上
user_id 映射**：

| 版本 | 组件 | 内容 |
|------|------|------|
| v5 | D1 + D3 | D1：威胁等级乘上对手平均副露组数（副露越多越危险）；D3：高威胁下若鸣牌被迫打的牌仍然危险（> cap 2.0）则放弃鸣牌 |
| v6 | E3 | 听牌平局按安全度取舍：多个弃牌保持听牌且（点数、听口数）完全相同时，优先打更安全的张，而不是无脑甩摸入张 |
| v7 | D3（纯） | 只做 D3，威胁用 v3 原版（隔离 D3 单独效果） |

### 10.1 重要背景：虹雀² 的手牌模型（本次厘清）

- 每手 **11 张**，摸牌后 12 张行动；**和牌 = 12 张全部属于 ≥3 张的合法组**，
  **没有雀头/将牌**（`win_check.py` 明确“同数对子不是和牌型”）。
- 因此**不存在单骑（tanki）听**；听牌形态只有“3 组 + 2 张连/嵌待”这类 ≥2 张的
  待牌。单副本库 + 自己手里的牌都算可见 → 听牌张经常快速变死，多面听少见。
- 组牌节奏：约 9 次摸牌内要组出 4 组，**先和牌的人结束本小局**——这是
  “和牌 = 结束 = 竞速”机制的核心。

### 10.2 同块 A/B 结果（各 400 场 = 6400 小局）

| 版本 | 块 | 均顺 | 净分（/大场） | vs v3 判定 |
|------|----|-----:|-----:|------|
| v5 (D1+D3) | 73001 | **2.748** | −2121（≈−5.3） | **惨败** |
| v7 (D3) | 73401 | **2.550** | −1208（≈−3.0） | **败** |
| v6 (E3) | 73401 | 2.4675 | −283（≈−0.7） | 中性，微优不显著 |
| v6 (E3) 复验 | 73601 | 2.475 | +80（≈+0.2） | 同上 |

（对照：v3 三座在同一块内自身波动就达 2.38–2.61，跨块方差极大，单块只有
同块 A/B 才可比。v6 两块结果高度一致：2.4675 / 2.4750，均 < 2.5。）

### 10.3 结论

1. **防守加码在 1v3 自战里全是负收益**：D3（鸣牌抑制）单独就输（2.55），
   D1（副露加权威胁）叠加后更糟（2.75）。v4（得分预期 × 威胁衰减）与 v5/v7
   指向同一教训——**虹雀² 是短手牌竞速游戏，防守换来的“少放铳”抵不过
   “自己慢和牌把分喂给三对手”**；v3 的威胁门控已接近这个维度上的局部最优。
2. **D3 是 v5 崩盘主因**：v5（D1+D3）= 2.75 → 纯 D3 = 2.55，D1 是叠加伤害。
3. **E3 是唯一不亏损的微调**：不改折叠、不改鸣牌，只在“已经听牌且弃牌选择
   完全等价”时避免放铳。800 场合并均顺 ≈2.47（两块的 2.4675/2.4750），
   方向稳定但 CI 上界 ~2.55 **未达显著线**（对比 v3 当年 vs 牌效 CI 上界 < 2.5
   的标准）——**达不到“明显优于 v3”的上线门槛**。
4. **线上维持 v3 不变**；v5/v6/v7 保留为实验代码 + 单测（与 v4 同级对待），
   文档记录取舍依据，防止后人重复踩坑。

### 10.4 后续方向建议（供下次探索）

- **进攻侧优先**：1v3 自战对防守型微调极敏感，进攻节奏（更快听牌、更宽听口、
  弃牌节奏、鸣牌时点）比任何防守细化都更有希望。
- **指标改进**：1v3 的“喂分”会把小优势稀释掉（v6 净分一块 −283 一块 +80）；
  若要鉴别微调，考虑 4 座同策略对局或更大的同块样本。
- **鸣牌成本意识**（本次未测）：鸣牌 = 丢掉门清 +2 base 与 门清 1 番 + 暴露方向，
  但 D3“抑制鸣牌”已证明过头——正确写法应是“鸣牌但更早冲刺”，不是“不鸣牌”。
